# ズボラ家計簿

**使った金額。残せるお金。**

金額だけを入力して、給料日までに残せるお金を確認する React アプリです。カテゴリ分けは不要。カレンダーから1日の合計額を記録でき、固定費は前期から自動で引き継ぎます。バックエンドやアカウントは不要で、データはブラウザの localStorage に保存されます。

## 起動

```sh
npm install
npm run dev
```

```sh
npm test
npm run build
npm run preview
```

## 使い方

1. 「設定」で毎月の手取り額（ボーナスを除く）、給料日（初期値25日）を登録。
2. 「固定費・臨時支出」で家賃、光熱費の概算、選択した月期だけの出費を登録。
3. 日々の生活費を記録。使わなかった日は「今日は支出なし」で記録。
4. 「残せるお金」でこの月期に残せるお金（最大）、選択した月期の1日平均を確認。

支出は「明細」を開くと編集・削除できます。「支出の記録」のカレンダーでは、日付をタップすると入力画面が開き、1日の合計額だけを入力できます。「保存」で入力画面を閉じ、次に入力する日をカレンダーで選べます。0円も記録できます。記録済みの日は合計を編集でき、金額を変更した場合はその日の明細を1件にまとめてメモを引き継ぎます。「未記録に戻す」でその日の支出と記録を削除できます。カテゴリ入力は不要です。固定費・臨時支出を日々の支出にも入力すると二重計上になるため、どちらかにだけ入力してください。

## 計算

期間は本来の給料日の月で「10月期（10/23–11/24）」のように表示します。休日の前倒しで給料日が前月に入る場合も、本来の支給月を使います。

- 給料日は土日なら直前の平日に前倒し。日本の祝日を避ける設定は初期値で有効です。月にない日付は月末として扱います。
- 現行の日本の祝日規則に対応（2020〜2099年、振替休日・国民の休日と2020・2021年の移動を含む）。銀行独自の休業日や年末年始の銀行休業日は含みません。将来の法改正にはコードの更新が必要です。
- 残せるお金（最大） = 手取り − 固定費 − 選択した月期の臨時支出 − 記録済みの生活費。未記録の支出や今後の生活費は差し引きません。赤字の場合は負数で表示します。手取り未設定の場合は「—」（主表示は「手取りを設定」）と表示します。
- 選択した月期の1日平均 = 選択した月期の生活費合計 ÷ 記録日数。「支出なし」で記録した日も含み、未記録日は平均の対象から除きます。未記録の期間は「—」と表示します。固定費・臨時支出は含めません。
- 固定費は月期ごとに保存します。新しい月期は前期の固定費を自動で引き継ぎます。しばらく使っていない場合は最後に設定した月期から引き継ぎます。臨時支出は引き継ぎません。固定費を削除して空にした月期も記憶するので、削除済みの費用を再作成しません。名前を押すと名前・金額を編集できます。ほかの月期の固定費には影響しません。既存の全期間共通の固定費は、更新後の初回読み込み時（旧バックアップは読み込み時）の現在の月期に引き継ぎます。
- 手取りの設定は全期間に共通です。収入の月別管理・銀行残高との同期はありません。
- 固定費・臨時支出は期間開始日で管理。給料日の変更で開始日が変わった場合、該当の固定費・臨時支出を再登録してください。

## 保存

「設定」からJSONのバックアップを書き出し・読み込みできます。ブラウザのストレージを消去すると記録も失われます。プライベートブラウズでは終了時に削除される場合があります。ストレージへのアクセスに失敗した場合は画面に表示します。サーバーへの支出データの送信はありません。フォントは端末のシステムフォントを使用し、外部のフォント配信サービスへの通信は行いません。

React / TypeScript / Vite / Lucide React。UIは日本語、円単位です。

アプリ名変更前の保存データもそのまま利用できます。バックアップのファイル名は `zubora-kakeibo-YYYY-MM-DD.json` です。

## 入力と中断・再開

- `580＋920` のように足し算で入力できます。
- 記録済みの日は「金額を追加」が初期値です。「合計を変更」でその日の合計額を修正できます。
- 入力途中の式と入力モードは、確定済みの支出とは別にブラウザへ下書き保存します。下書きは残額に反映しません。
- 下書きがあればホームから再開できます。保存後はその日の下書きを削除します。
- 今日の記録を保存すると残額画面へ戻ります。過去の日付ではカレンダーに戻ります。
- 初期設定はホームでは折りたたみ表示です。記録を始める前の完了は必須ではありません。
- カウントダウンは日・時間・分・秒を表示し、毎秒更新します。

現時点ではアクセス解析・広告のコードは導入していません。家計データはサーバーに送信しません。外部のフォント配信サービスも使用していません。

## 紹介ページ

`/about/` に設計の理由・操作サンプル・プライバシー方針を説明するLPがあります。アプリは引き続き `/` です。設定から紹介ページに移動できます。操作サンプルは実際の家計データを読み書きしません。Viteの複数HTMLエントリーでビルドするため、静的配信でも `dist/about/index.html` を直接配信できます。

プライバシーポリシーは `/privacy/` です。設定画面と紹介ページのフッターから移動できます。運営者名・問い合わせ先は `src/siteInfo.ts` に設定するとページに表示されます。

効果的な使い方は `/tips/` です。サイドバー下部の設定の直下、設定画面内、LPのフッターから開けます。PWAのオフライン表示にも対応しています。

## 最大値とペース予測

最大値は従来どおり、毎月の基本の手取りから固定費・臨時支出・記録済みの生活費を引いた額です。現在の月期では、その下に「このペースで残せるお金」を表示します。記録した日（0円を含む）の平均支出 × これからの日数を最大値から差し引き、円未満を切り捨てます。今日を記録済みなら明日から、未記録なら今日から見積もります。未記録の日と下書きは平均に含めず、過去の未記録支出の補完もしません。収入未設定・記録なしの場合は予測を表示しません。赤字も負数のまま表示します。

目指すのは予測額以上を残すこと。ボーナス・残業代は入力せず、貯金の上乗せにします。曖昧な支出は多めに見積もり、固定費やカード払いの二重記録は避けます。予測額は記録に応じて変化し、保証額や固定の目標ではありません。

## ホーム画面への追加

manifest・PNGアイコン・本番ビルド時に生成するService WorkerでPWAに対応しています。HTTPSまたはlocalhostが必要です。画面と静的ファイルを端末にキャッシュし、家計データは従来どおりlocalStorageに保存します。開発サーバーではService Workerは登録しません。

初回の支出（0円を含む）記録後、追加可能イベントを受け取ったブラウザ、またはiOSで一度だけ案内します。設定から手動で再表示できます。standaloneでの起動とappinstalledイベントを検出したら案内を隠します。全ブラウザ共通のインストール済み判定はできず、別端末・別ブラウザの状態も取得しません。案内の表示状態はバックアップ対象の家計データとは別に、このブラウザに保存します。

ブランド方針：ズボラ家計簿「ざっくりつけて、ちゃんと残す。」。収入は控えめ、曖昧な支出は多めに見積もり、貯金を多く見込みすぎない。最低貯金額の保証を意味しません。既存の保存キー・インストール案内キー・PWAのidは互換性のため維持します。
