# 開発メモ

React / TypeScript / Vite / Lucide React。UIは日本語、円単位です。

## 計算と記録

計算の実装は `src/finance.ts`、検証は `src/finance.test.ts` を参照してください。

- 月期は本来の給料日の月で表し、支給日から次の支給日の前日までを扱います。
- 給料日は土日・設定に応じた日本の祝日を避けて前倒しします。月にない日付は月末にします。
- 祝日の実装は2020〜2099年を対象にしています。銀行独自の休業日・年末年始の銀行休業日は含みません。法改正には更新が必要です。
- 最大額 = 手取り − 固定費 − その月期の臨時支出 − 記録済みの生活費。今後の生活費と未記録の支出は含みません。
- ペースからの見積もり = 最大額 − 記録日の平均生活費 × これからの日数。今日を記録済みなら明日から、未記録なら今日から見積もります。
- 0円の記録は平均に含め、未記録の日と下書きは除きます。未記録分を推測で補いません。手取り未設定・記録なしでは見積もりを表示しません。
- 赤字は負数のまま表示します。見積もりは最低貯金額の保証ではありません。
- 手取り設定は全期間共通。ボーナス・残業代は入力せず、貯金の上乗せとして扱います。
- 固定費は月期別に保存し、新しい月期へ直近の設定を一度だけ引き継ぎます。空にした設定も維持し、臨時支出は引き継ぎません。
- 費用の月期キーは期間開始日です。給料日変更で開始日が変わる場合は再登録が必要です。
- 固定費・臨時支出を日々の生活費にも入力すると二重計上になります。

## 保存と互換性

保存失敗・競合時の保護と回帰テストは [STORAGE.md](STORAGE.md) を参照してください。

家計データは家計簿オリジンのlocalStorageに保存します。データ形の検証・旧データの移行は `src/finance.ts`、読み込み・書き出しは `src/App.tsx` にあります。

- 家計データの保存キー `yohaku-money-v1` とインストール案内のキー `nokori-install-v1` は、過去のアプリ名から引き継いでいます。
- 入力途中の式は下書きとして保存し、確定するまで残額に反映しません。
- 保存データが不正な場合は、元データを上書きしないよう自動保存を止めます。
- ブラウザ・端末・オリジンごとに記録は独立します。データ削除や機種変更に備え、JSONのバックアップを使います。
- 旧LPオリジンからの移行は `src/Migration.tsx`。手順は [DEPLOY.md](../DEPLOY.md) を参照してください。

## ビルドとPWA

開発は `npm run dev` でLPを5173、家計簿を5174に同時起動します。ポート変更による保存先の混乱を避けるため、使用中なら別ポートに自動変更せず終了します。リンク先のホスト名は開いている開発ページに揃えます。片方だけの起動には `npm run dev:site` / `npm run dev:app` を使えます。

- `npm run build` はLPを `dist`、家計簿を `dist-app` に生成します。
- エントリーはLPが `src/main.tsx`、家計簿が `src/app-main.tsx`。家計簿のビルドモードは `app` です。
- 家計簿はルートURLから起動し、Service Workerで同一オリジンの静的ファイルをキャッシュします。家計データをService Workerへ移しません。
- LPのService Workerは旧キャッシュを解除する移行用です。localStorageを自動削除しません。
- 開発サーバーではService Workerを登録しません。PWAの確認には本番ビルドとHTTPSまたはlocalhostを使います。
- ホーム画面からの起動等を検出すると追加案内を隠します。通常のブラウザからインストール済みかを常に判定できるわけではありません。
- `scripts/check-dist.mjs` で両ビルドのファイル・CSP・広告コードの除外を検査します。

## セキュリティと変更の取り込み

`master`はPR必須です。`Test and build`・`Gitleaks`の成功と最新の本番ブランチへの追従が必要です。強制push・削除は禁止し、管理者にも適用しています。個人開発のため他人の承認は必須にしていません。

新しくcloneした環境ではローカルの秘密情報検査も有効にします（macOS）。

```sh
brew install gitleaks
npm run hooks:install
npm run security:scan
```

コミット前はステージ済み変更、push前は全履歴を検査します。Gitleaks未導入時も停止します。フックは各cloneで有効化が必要で、GitHub側のSecret Scanning・Push Protectionと併用します。

CIは `npm ci` → テスト → 両ビルド → 公開ファイル検査と、別のGitleaksワークフローを実行します。Actionsは読み取り権限で、Cloudflareのデプロイ用Secretsは使いません。

家計簿とLPのオリジン分離、CSP、Cloudflareの設定は [DEPLOY.md](../DEPLOY.md)、広告の扱いは [ADSENSE.md](../ADSENSE.md) を参照してください。運営者・問い合わせ先は `src/siteInfo.ts` で設定します。
